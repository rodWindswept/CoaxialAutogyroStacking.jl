## What changed

### 1. Bug fix: `solve_polygon_angles` (src/polygon_line.jl)

The force equilibrium at each rotor vertex had three errors:

| Issue | Old (buggy) | Correct |
|-------|------------|---------|
| Force magnitude | `F_line = T·cos(δ)` | `T` (disk-normal thrust) |
| Angle inside trig | `θ + δ` | `θ − δ` (via `effective_alpha()`) |
| Trig functions | `sin` for x, `cos` for y | `cos` for x, `sin` for y |

At the top_draggy design point (θ=55°, δ=20°), the old code computed −7°
(clamped to 5° by a safety clamp). The correct angle is 39°. Error: 46°.

The correct equilibrium is:
```
α_eff = 90° − θ + δ          # disk-normal angle (same as effective_alpha)
T_x = T_above·cos(θ) + T·cos(α_eff)
T_y = T_above·sin(θ) + T·sin(α_eff) − W
θ_new = atan(T_y, T_x)
```

An under-relaxation damping factor (ω=0.5) was added because the corrected
physics exposed a thrust↔angle oscillation: flat angle → high through-disk
velocity → large thrust → steep angle → low velocity → small thrust → flat
again. The bug's 5° clamp was masking this oscillation.

Full derivation: `Desktop/Teach Co-ax-autoG/lessons/0002-force-projection.html`

## Why the old tests passed despite 46° error

Most polygon tests used δ ≈ 0° (where sin/cos swap cancels out), tolerances
were ±30°, and the 5° clamp hid negative angles. The steep-anchor test
(θ_steep > 55°) had to be updated — with corrected physics, the single-rotor
equilibrium is independent of the anchor angle initial guess.
